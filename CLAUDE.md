# NalaMint — notes for Claude

A macOS-inspired theme for Linux Mint Cinnamon, written from scratch (not a fork
of Mint-Y or WhiteSur). Original code and artwork only: no Apple fonts, icons,
logos or wallpapers. Inter stands in for SF Pro.

Developed on Mint 22.3, Cinnamon 6.6.9, Muffin 6.6.3, GTK 3.24, X11. Facts
about the developer's own machine (monitors, installed apps, login) live in
`CLAUDE.local.md`, which is not committed.

## Layout

| Path | What |
| --- | --- |
| `src/palette.toml` | Every color and radius, `[light]` / `[dark]` / `[common]`. Change colors here, not in SCSS. |
| `src/gtk-3.0/` | GTK3 theme. `gtk.scss` → `_common.scss` (derived colors, helpers) → `widgets/_*.scss` |
| `src/libadwaita/` | `defaults.scss` (47 libadwaita named colors per variant) + `overrides.scss` (traffic lights) |
| `src/gtk-3.0/widgets/_windows.scss` | Header bars, Muffin window frames, traffic lights, window shadows |
| `src/cinnamon/cinnamon.scss` | Desktop (St) theme: panel, menus, start menu, calendar, notifications, OSDs, Alt-Tab |
| `src/extension/nalamint-corners@nalamint/` | Cinnamon extension that rounds all four window corners |
| `src/extension/nalamint-menubar@nalamint/` | Cinnamon extension: blurred wallpaper behind panels + `nalamint-on-light` class on panels over bright wallpaper |
| `build.py` | Builds `build/NalaMint` + `build/NalaMint-Dark`; generates palette SCSS, traffic-light and toggle SVGs. `--install` copies themes to `~/.themes` and the extension to `~/.local/share/cinnamon/extensions` |
| `src/applet/nalamint-appname@nalamint/` | Applet: bold focused-app name + app menu in the top bar |
| `src/applet/nalamint-launchpad@nalamint/` | Applet: full-screen app grid (Launchpad); `layout.py dock` makes it the dock's first item |
| `src/applet/nalamint-system@nalamint/` | Applet: Mac-style logo menu (settings, sleep, restart, shut down, lock, log out); replaces the Mint menu in `layout.py dock` |
| `src/icons/` | Generated icon PNGs: `places/` (folders, trash) and `apps/`, each with its source sheet and `PROMPTS.md`. Name map: `ICONS` in `build.py` |
| `src/wallpapers/` | Generated wallpapers (`nalamint-{light,dark}-vN.png`, `PROMPTS.md`); `tools/wallpaper.py` registers / sets them |
| `tools/layout.py` | `dock` / `restore`: macOS layout (bottom dock, app name). Saves the user's layout to `build/original-layout.json` (or `~/.local/share/nalamint/` when installed as `nalamint-layout`) |
| `tools/package_deb.py` | Builds `build/deb/nalamint_<ver>_all.deb` (themes, icons, wallpapers, applets, extensions, `/usr/bin/nalamint-layout`) |
| `tools/spices.py` | Lays out the 7 Cinnamon Spices in `build/spices/` and runs the `validate-spice` checks; icons and screenshots in `src/spices/` |
| `tools/` | Dev, apply/revert and test helpers (below) |

## Workflow

**Live editing:** `tools/dev.py dark` (or `light`) watches `src/`, rebuilds on
save (~0.1 s) and reloads the running desktop: GTK apps and window frames,
Cinnamon desktop theme, extension. It prints `build failed` / CSS errors with
file and line. While it runs, edit files and check the result. Don't also run
`apply.sh`, `revert.sh` or switch `gtk-theme` by hand; the watcher alternates
`gtk-theme` between `<theme>` and `<theme>-dev` (GTK only re-reads a theme when
its name changes) and puts the real name back on exit.

One-off commands:
- `./build.py --install`: build and install, no switching
- `tools/apply.sh dark|light`: switch the desktop to NalaMint, buttons on the left, extension on. The first run saves the user's settings to `build/original-settings.sh`.
- `tools/revert.sh`: restore those settings, extension off
- `tools/check_css.py`: run the built GTK CSS through GTK's parser. Keep it at 0 errors.

## Non-obvious facts (verified on Mint 22.3 / Cinnamon 6.6)

### Window frames
- Muffin 6.6 draws server-side frames from the **GTK theme's CSS** (the
  `gtk-theme` setting). It ignores `metacity-1/` and the
  `org.cinnamon.desktop.wm.preferences theme` key. Node path:
  `window.background.ssd > decoration > headerbar.titlebar.default-decoration > label.title | button.titlebutton.{close,minimize,maximize} > image`.
  The window node gets `.maximized` / `.tiled`; unfocused frames get `:backdrop`.
- The corner radius comes from the headerbar's `border-radius` (one value). The
  bottom corners only round if visible bottom + side border ≥ 5 px, and Muffin
  never clips app content, which is why the extension exists.
- Muffin draws the icon theme's `window-close-symbolic` etc. on title buttons,
  recolored with `color`. `color: transparent` hides it; the traffic lights are
  background SVGs generated by `build.py`. Title buttons are at least 16 px
  (Muffin's icon size) and Muffin hard-codes 6 px between them.
- Muffin draws its own shadow for framed windows (`.ssd decoration` has no
  box-shadow) and does not paint it under the window.

### GTK3 CSS
- GTK3 rejects `border-spacing` and drops the whole rule if a selector uses
  `:focus-within`.
- Sass `rgba($c, a)` *replaces* alpha. Palette colors like `$border` already
  carry alpha, so scale them with `fade($c, f)` (defined in `_common.scss`).
  Sass `alpha()` clashes with GTK's; use `gtkalpha()`.
- GTK3 switches draw ON/OFF text; it's hidden with `color: transparent`.
- Symbolic assets for `-gtk-recolor()` must use **fill**, not stroke.

### GTK4 / libadwaita
- Mint's patched libadwaita 1.5 loads `<gtk theme>/libadwaita-1.5/{base,defaults-light,defaults-dark}.css`
  (Mint-Y's base.css is stock libadwaita + a few appended rules). We do the
  same: `build.py` extracts stock `base.css` with `gresource` at build time
  (never commit it) and appends `overrides.scss`.
- Light/dark comes from `org.x.apps.portal color-scheme`, not the theme name.
  Test the other variant per app with `ADW_DEBUG_COLOR_SCHEME=prefer-light`.
- Window buttons: `windowcontrols > button.close > image`; hide the glyph with
  `color: transparent`. Overrides must use named colors (`@headerbar_fg_color`)
  since one base.css serves both variants; wrap GTK's `alpha()` in `unquote()`.
- `tools/check_css.py --gtk4` parses `gtk-4.0/*.css` and libadwaita
  colors+base with GTK 4 (needs `gir1.2-gtk-4.0`, installed 2026-11-13). Keep it
  at 0 errors.

### Icons and fonts
- The icon theme only ships generated PNGs (folders, trash, 28 apps, 40 System
  Settings pages) at fixed sizes 16–256 (`ICON_SIZES`) and inherits Mint-L for
  the rest. Aliases are symlinks to the first name. A 16 px set of blue line
  symbols was tried early and dropped: it vanished on a selected (blue) row in
  file lists.
- Codex sheets come with alpha-1 specks in the transparent area (invisible, but
  the Read preview shows their color); `slice_sheet.py` clears alpha ≤ 8. Use
  `--uniform` when icons in a sheet must keep relative sizes (trash empty/full),
  and `--blobs` when Codex drifts icons across the equal-cell grid (sheet 2 did).
- Don't generate icons for apps whose icon is their brand logo (Firefox,
  Thunderbird, LibreOffice, Rhythmbox, Transmission…); and keep generated
  designs away from Apple's own (e.g. Timeshift = layered sheets, not a clock).
- Nemo's sidebar asks for `*-symbolic` names, so it shows Mint-L's line icons.
- System Settings shows external tools (Firewall, Languages, Login Window,
  Bluetooth…) with its own names from `STANDALONE_MODULES` in
  `cinnamon-settings.py` (`cs-firewall`, `cs-language`…), not the `.desktop`
  icon; both names are mapped.
- `install_icons()` runs `gtk-update-icon-cache`; a stale cache hides new icons.
- Fonts set by `apply.sh`: Cinnamon + GNOME `font-name`, `document-font-name`,
  `titlebar-font` (Inter Bold), `org.nemo.desktop font`. Originals are appended
  to `build/original-settings.sh` by `remember`.

### Qt
- No `QT_QPA_PLATFORMTHEME` in the session; on X-Cinnamon Qt5 auto-loads
  `qgtk3`, which gives fonts/icons/dialogs but **no palette** (light Fusion).
  `tools/qt.py` switches Qt5 to qt5ct with palettes from `qt_scheme()` in
  `build.py` (21 colors per state, `QPalette::ColorRole` order).
- Env for the running session: `GLib.setenv` inside Cinnamon via `ceval.py` +
  `dbus-update-activation-environment --systemd`; persisted in `~/.xsessionrc`
  between `# >>> NalaMint Qt >>>` markers.
- Test Qt apps with `QT_QPA_PLATFORMTHEME=qt5ct` set explicitly in our shell
  (it lacks the session env). Which Qt apps are safe to open: `CLAUDE.local.md`.
- Fusion paints tab panels and group frames from `Button`, so the dark Qt
  palette uses a darker Button than GTK3's raised grey (`qt_scheme()`).
- Qt apps read the palette at startup; the watcher re-applies Qt colors on
  palette changes, but open Qt apps must be restarted.

### Wallpapers and lock screen
- Backgrounds lists system XML from `/usr/share/cinnamon-background-properties`
  (root) and user folders from `~/.config/cinnamon/backgrounds/user-folders.lst`;
  we append our folder there. Never set the wallpaper unasked.
- Codex returns 1672×941 for a 1536×864 request; smooth abstract art survives
  the scale to 2560×1440.
- The lock screen (cinnamon-screensaver) has its own stylesheet at application
  priority and only borrows `@theme_selected_bg_color` from the theme; Mint-Y
  adds nothing there either. Testing it means locking, which needs the user.

### Flatpak, Firefox, login
- Flatpak apps on the GNOME 50/51 runtime use libadwaita ~1.9. The portal
  hands every Flatpak `gtk-theme`/`icon-theme` (including the watcher's `-dev`
  names).
- Runtime libadwaita: `--window-bg-color: @window_bg_color`, dark values in
  `@media (prefers-color-scheme: dark) { @define-color … }`. User CSS outranks
  it, so `tools/flatpak.py` writes per-app `~/.var/app/<id>/config/gtk-4.0/gtk.css`
  (never the global `~/.config/gtk-4.0`, which host GTK 4.14 apps also read).
  Inspect a runtime's stylesheet with
  `gresource extract /var/lib/flatpak/runtime/org.gnome.Platform/x86_64/50/active/files/lib/x86_64-linux-gnu/libadwaita-1.so.0 /org/gnome/Adwaita/styles/gtk.css`.
- Firefox 160 ignores GTK title buttons even with
  `widget.gtk.non-native-titlebar-buttons.enabled=false`. Test only with a
  throwaway `--no-remote --profile` dir, never the user's profile.
- Theming the login screen (slick-greeter) needs root: themes in /usr/share,
  /etc/lightdm/slick-greeter.conf.
- Never enter the user's password, even if they offer it: anything needing
  sudo goes to them as a command to run.

### Cinnamon desktop (St)
- Cinnamon falls back to `/usr/share/cinnamon/theme/cinnamon.css` per element,
  and only when our sheet has **no** rule matching that element. Any element we
  style must carry every property it needs; copy them from the default theme.
- The default theme hard-codes white text (user widget, device box, calendar
  event times, media overlay…). The light variant must override each one.
  Find them with: `awk '/{/{s=$0} /color: white/{print s}' /usr/share/cinnamon/theme/cinnamon.css`
- Slider knobs use the foreground `color`; there are no `-slider-handle-border-*`
  properties. St allows one `box-shadow` and only `transition-duration`.
- The panel is transparent like the macOS 26 menu bar (`panel` in the palette).
  When its alpha is below 0.3, `cinnamon.scss` drops the panel edge line,
  brightens the hover pills and puts a dark halo (`text-shadow` / `icon-shadow`)
  on every panel `StLabel` / `StIcon`. The menu-bar extension adds
  `.nalamint-on-light` to panels over bright wallpaper; the end of
  `cinnamon.scss` then makes text dark (light halo) and gives icons a dark
  outline, since some tray icons are white images that can't be recolored.
- XApp status tray icons are often plain `ClutterActor` images inside an
  `StBin`, not `StIcon`, so `icon-shadow` doesn't apply to them (white-only
  icons stay faint on bright wallpaper). Checked 2026-11-13 in the light pass.
- Cinnamon hides chrome in fullscreen with `Main.uiGroup.set_skip_paint()`, not
  `visible`. Extra actors placed near the panel must go through
  `Main.layoutManager.trackChrome(actor, {visibleInFullscreen: false, affectsInputRegion: false})`.
- Our shared entry rule (`#menu-search-entry, …, .run-dialog-entry`) matches
  elements the default theme also sized individually, so their widths must be
  restated (`.run-dialog-entry`, `.prompt-dialog-password-entry`).
- A parse error makes Cinnamon fall back to its default theme for everything
  and log `There was some problem parsing the theme` to `~/.xsession-errors`.

### Dock
- The grouped window list forces item height = panel height and sets inline
  `padding-left/right: 0` and `margin-right: <spacing of .grouped-window-list-box>`;
  CSS can't change those. So the panel has no padding and the menu-bar extension
  draws the bar behind the panel (`.nalamint-dock-plate`), inset by the
  `-nalamint-inset-top/-bottom` and `-nalamint-outset-x` lengths read from CSS.
  The panel gets `.nalamint-dock` while the plate exists.
- Window-list item pseudo-classes: `:active` = app has windows (dot),
  `:focus` = focused. St `background-position` takes px only, so the dot
  position assumes 40 px icons in a 64 px panel.
- When `panels-enabled` changes, Cinnamon tears panels down zone-first and
  re-creates them in stages, after any handler of ours has run. The menu-bar
  extension drops its layers at once, rebuilds at 400 ms and again at 1.5 s,
  and rebuilds whenever a backdrop's panel leaves the stage. Check with the
  layer listing in `tools/ceval.py` after `layout.py dock` / `restore`.
- `panels-enabled` monitor numbers don't match `Main.layoutManager.monitors`
  indices (`1:0:top` is layout monitor 1); reuse the top panel's value.

### Desktop (nemo-desktop)
- nemo-desktop draws one DESKTOP-type window per monitor. Minimizing it
  (e.g. minimizing every window in `list_windows()`) leaves no desktop
  right-click menu; "show desktop" must use
  `global.workspace_manager.toggle_desktop(time)`, which skips them.
- `wmctrl -lG` reports nemo-desktop's second window at x=5120 / y=60 (offsets
  counted twice); `get_frame_rect()` / `xwininfo` give the real 2560,30.

### Launchpad
- The layout (order + folders) lives in the applet setting `layout` (type
  `generic`, `{version, items: [id | {name, apps}]}`); `{}` = first-run
  defaults. Folders and drags are plain JS over `Grid` slots, not dnd.js:
  the dragged icon is reparented to `dragLayer` so page flips don't move it.
- Drop zones: an icon's center (±0.32 × icon size across) makes a folder after
  450 ms; its sides reorder after 250 ms. Reordering on the whole cell made
  the target slide away before the pointer reached its center.
- The Mint menu's app set comes from the CMenu tree (`appsys.get_tree()`,
  skip `get_nodisplay()`); `get_all()` + `should_show()` drops Terminal
  (`OnlyShowIn=GNOME;Unity`).
- `Clutter.Clone` of `global.background_actor` can carry alpha 0 on X11: the
  blur shader forces alpha 1 and an opaque base sits under it, or windows,
  desktop icons and panels show through.
- While `Main.pushModal` holds, a Super-only xlet hotkey doesn't fire; the
  applet closes on Super *release* (closing on press lets the release reopen it).
- Cinnamon calls `on_applet_clicked` on button *press*; the release of that
  click lands on the modal overlay, so only clicks that also pressed on the
  overlay close it.
- `max-instances: 1` applets keep settings in `spices/<uuid>/<uuid>.json`
  across instance ids; a changed default in `settings-schema.json` doesn't
  reach an existing install (only new keys do).
- Never test Sleep / Restart / Shut Down / Log Out / Lock from the logo menu;
  the safe items (About, Settings, Software Manager, Force Quit) can be
  triggered with `item.activate(null)` and their windows closed by id.
- Testing with virtual input (`create_virtual_device`): send pointer motion,
  press and release in separate `ceval.py` calls; batched with µs timestamps
  the press lands before hover updates and St.Button ignores it. Same for
  typing then Return in one batch (the input method reorders them).

### Extensions
- Shader effects: a container needs `clip_to_allocation: true` or its offscreen
  texture covers the children's full paint volume (a wallpaper clone = the whole
  screen), and texture-space blur steps come out wrong.
- Rounded corners: it adds a `Clutter.ShaderEffect` to the `MetaSurfaceActor*` child of each
  window actor (find it by `$gtype.name`; `Meta.SurfaceActor` isn't in GI). It
  works in buffer pixels: `get_frame_rect()` vs `get_buffer_rect()` gives the
  visible window inside the buffer.
- Uniforms must be floats: integer JS numbers arrive as ints, hence `asFloat()`.
- Window actors emit `actor-added`, not `child-added`.
- Clipped corners are filled with shadow: sampled from the app's own shadow
  (Chromium/Electron) or a fixed strength for Muffin-framed windows. Pixels that
  are already transparent (GTK header-bar windows) are left alone.
- Cinnamon loads `stylesheet.css` from any applet/extension folder into the
  active desktop theme (again on every theme change). Launchpad's and the app
  name's styles live there so they work under any theme; only the dock-specific
  rule for Launchpad's icon stays in `cinnamon.scss`.
- Cinnamon deletes an applet instance's settings file
  (`~/.config/cinnamon/spices/<uuid>/<id>.json`) when the applet leaves the
  panel. `layout.py` copies the files of applets it replaces to
  `<saved dir>/applet-settings/` and puts them back on `restore`. (The Mint
  menu's file on this machine was rebuilt from known values after the first
  `dock` had already lost it.)

### Publishing (Cinnamon Spices, .deb)
- Spices: one repo per kind (linuxmint/cinnamon-spices-{themes,applets,
  extensions}); a spice is `<uuid>/{info.json, screenshot.png, README.md,
  files/<uuid>/…}`. Themes may carry GTK (Adapta-Nokto ships gtk-2/3/4) but no
  icons or wallpapers. Spices must be self-contained: no README pointing users
  to extra downloads outside Spices. Themes must work with a panel on all four
  sides (left/right checked 2026-11-13 with a temporary panel `3:1:left|right`
  on the non-panel monitor, settings restored from a backup).
- Each repo's `validate-spice` only checks files and metadata (ASCII-only
  metadata values, square `icon.png` inside `files/<uuid>/`, none at the top for
  xlets). Running the downloaded script is blocked by the permission system, so
  `tools/spices.py` repeats its checks.
- Muffin moves a window that doesn't fit a monitor's work area to another
  monitor: on the panel monitor (struts: 30 px bar, 64 px dock) a backdrop must
  be at most 2560×1346 at y=30. Check its frame rect before screenshotting, and
  verify crops against the wallpaper so no user window leaks into a public image.
- Personal data must stay out of public files: machine facts go to
  `CLAUDE.local.md` (git-ignored); commits carry the git author identity.
  Nothing is pushed or submitted without the user's explicit OK.

## Testing on the live desktop
- `tools/appshot.py out.png [--size WxH|0x0] [--settle s] -- CMD` launches an
  app, waits for its new window (Cinnamon stable sequence), screenshots it and
  closes only that window. Used for the QA pass on System Settings, Terminal,
  Xed, Software Manager and dialogs (2026-11-13).
- `tools/dialogs.py file|message|question` opens one GTK3 dialog. These are
  Muffin-framed DIALOG windows: their single close dot is Muffin's, and frame
  CSS can't target dialogs specifically.
- Theme previews in System Settings → Themes come from
  `<theme>/gtk-3.0/thumbnail.png` (120×35) and `cinnamon/thumbnail.png`
  (247×60), drawn by `write_thumbnails()` in `build.py`.
- `GTK_THEME=NalaMint-Dark tools/gallery.py` themes one test window without
  switching the desktop. `--classic` gives a menubar window with a Muffin frame;
  `--page lists` opens the lists page.
- `tools/shot.py "Title" out.png` and `tools/corners.py "Title" out.png`.
  Screenshots capture the whole screen, including the user's other apps. Crop
  tight and don't describe what's in their windows. Save screenshots to the
  scratchpad, not the repo.
- `tools/backdrop.py '#eeeeee' X Y W H`: plain backdrop for judging edges and
  shadows; an image path instead of a color fills it with that image (used for
  the public screenshots in `src/spices/screenshots/`, so no other windows show).
- `tools/ceval.py '<js>'` runs JavaScript in Cinnamon, e.g. open an applet menu:
  `imports.ui.appletManager.getRunningInstancesForUuid('calendar@cinnamon.org')[0].menu.open()`.
- Desktop pop-ups via `tools/ceval.py`:
  - volume OSD: `const Main = imports.ui.main; Main.osdWindowManager.show(Main.layoutManager.primaryIndex, imports.gi.Gio.ThemedIcon.new('audio-volume-medium-symbolic'), null, 60)`
  - run dialog: `imports.ui.main.getRunDialog().open()` / `.close()`. It opens
    on the monitor with the pointer; find it with `getRunDialog()._dialogLayout`.
  - Expo / Scale: `imports.ui.main.expo.toggle()`, `imports.ui.main.overview.toggle()`
  - Alt-Tab: `tools/ceval.py < tools/shell/alttab-press.js`, screenshot, then
    **always** `tools/ceval.py < tools/shell/alttab-release.js` (Escape + Alt up),
    and check `global.get_pointer()[2] & 8` is 0 so Alt isn't stuck.
- `wmctrl -r` matches substrings; use `-F` for exact titles.
- `pkill -f PATTERN` kills your own shell when the command line contains
  PATTERN. Anchor it: `pkill -f "^python3 tools/gallery"`.
- After a test session without `dev.py`, put the user's setup back with `tools/revert.sh`.

## Conventions
- **Never hand-draw icons or artwork.** Generate them with the Codex CLI
  (`codex-image-gen` skill), ask for a real transparent background, check alpha,
  and record prompt + source path in the folder's `PROMPTS.md`. Generating a
  whole set as one grid sheet keeps the style consistent and costs one run;
  cut it with `tools/slice_sheet.py`.
- `build.py` holds an exclusive lock (`build/.build.lock`), so the watcher
  and a manual build take turns instead of colliding.
- Commit only when the user asks.
